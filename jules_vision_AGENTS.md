# Инструкции для ИИ-агентов (jules_vision_AGENTS.md)

## 1. Стек и зависимости
Этот проект представляет собой шлюз Nextcloud Data Plane MCP.
- **Язык программирования:** Python 3.10+
- **Ключевые библиотеки:**
  - `mcp` (FastMCP) — для реализации протокола Model Context Protocol.
  - `httpx` — для асинхронных HTTP-запросов.
  - `pydantic` — для валидации данных и конфигурации.
- **Инструменты тестирования:** `pytest`, `pytest-asyncio` для асинхронных тестов, `respx` для мока HTTP-ответов.

## 2. Команды верификации
Перед сдачей работы (коммитом) ОБЯЗАТЕЛЬНО запускай следующие проверки:
- **Установка зависимостей проекта для разработки:**
  ```bash
  pip install -e '.[dev]'
  ```
- **Запуск всех тестов:**
  ```bash
  pytest
  ```
  *(или `python3 -m pytest -v` для подробного вывода)*

В текущей конфигурации проекта (`pyproject.toml`) не заданы строгие линтеры или форматтеры (такие как ruff, black, mypy), поэтому старайся придерживаться стиля написания исходного кода проекта и стандарта PEP-8.

## 3. Архитектурные особенности и правила кодинга
- **Асинхронность:** Все функции взаимодействия с внешними API (Nextcloud) должны быть асинхронными (использовать `async def` и `httpx.AsyncClient`).
- **Взаимодействие с API Nextcloud:**
  - WebDAV (`/remote.php/webdav`) — для операций с файловой системой.
  - OCS REST API (`/ocs/v1.php/cloud`) — для получения данных пользователя и квот.
  - Deck API и CalDAV — для досок Kanban и календаря.
- **Паттерн безопасности HITL (Human-In-The-Loop):**
  Критическая архитектурная особенность! Любые деструктивные операции или операции записи (`write_file`, `delete_file`, `create_folder`) защищены механизмом ручного подтверждения (HITL). Запрос не выполняется сразу, а возвращает токен (UUID). Для завершения операции нужно вызвать `execute_pending_action` с этим токеном.
- **Обработка ошибок API:** Перехватывай HTTP-ошибки и возвращай их в виде структурированного JSON словаря, например: `{"status": "error", "error": "описание"}`. Не допускай падения сервера из-за необработанных исключений при сетевых запросах.
- **Аутентификация:** Используется базовая авторизация (`BasicAuth`), где паролем выступает App Password (переменная `NC_APP_PASSWORD`), а не основной пароль пользователя.

## 4. Советы для будущих ИИ-агентов
- **Мокирование в тестах:** Никогда не делай реальные сетевые запросы к Nextcloud в тестах. Всегда используй `@respx.mock` и перехватывай нужные эндпоинты (`respx.get(...)`, `respx.route(method="PROPFIND")` и т.д.), возвращая объекты `httpx.Response`.
- **Внимательно с HITL:** Если твоя задача — "создать файл", помни, что вызов `write_file` — это только первый шаг. Тебе нужно перехватить `pending_approval` ответ с токеном, запросить (или сымитировать) подтверждение, и обязательно вызвать `execute_pending_action`, иначе файл не будет создан.
- **Ограничения `read_file`:** Этот инструмент предназначен **только для чтения текста**. Не пытайся использовать его для скачивания бинарных файлов (картинок, архивов), так как при декодировании в UTF-8 данные могут быть повреждены.
- **Нормализация путей WebDAV:** Пути к файлам всегда должны начинаться с корневого слеша `/` и не иметь лишних пробелов по краям.
- **Безопасность учетных данных:** В коде не должно быть хардкода учетных данных (логинов, паролей, токенов). Все конфигурации должны считываться только через функцию конфигурации окружения (класс `NextcloudConfig`).
