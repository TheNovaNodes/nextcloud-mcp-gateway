# Инструкции для ИИ-агентов (Jules Vision)

Добро пожаловать в репозиторий `nextcloud-mcp-gateway`! Этот файл содержит инструкции и лучшие практики, собранные мной (Jules) для будущих ИИ-агентов, чтобы работа с этим проектом была эффективной, безопасной и предсказуемой.

## 1. Стек и зависимости

*   **Язык:** Python 3.10+
*   **Фреймворк MCP:** [FastMCP](https://github.com/jlowin/fastmcp) (через библиотеку `mcp`)
*   **HTTP Клиент:** `httpx` (асинхронный)
*   **Валидация данных:** `pydantic`
*   **Тестирование:** `pytest`, `pytest-asyncio` для асинхронных тестов.
*   **Мокинг HTTP-запросов:** `respx` (обязателен для тестов, так как мы ходим в стороннее API).

## 2. Команды верификации

Перед отправкой любых изменений (Pull Request), вы **обязаны** убедиться, что код собирается и тесты проходят.

*   **Установка зависимостей (включая dev):**
    ```bash
    pip install -e '.[dev]'
    ```
*   **Запуск тестов и проверка покрытия:**
    ```bash
    python -m pytest -v --cov=nextcloud_mcp_gateway
    ```

## 3. Архитектурные особенности и правила кодинга

*   **Асинхронность:** Сервер полностью асинхронный. Все вызовы к Nextcloud API осуществляются через `httpx.AsyncClient`.
*   **Отсутствие проверки TLS:** В текущей реализации (`src/nextcloud_mcp_gateway/server.py`) клиент инициализируется с `verify=False`. Учитывайте это при анализе безопасности и сетевом взаимодействии.
*   **HITL (Human-in-the-Loop):** **Критически важно!** Любые деструктивные или пишущие операции (создание, изменение, удаление файлов/папок) защищены паттерном HITL. Агент не выполняет их напрямую, а возвращает токен `pending_approval`. Операция завершается только после подтверждения человеком через `execute_pending_action`.
*   **Авторизация:** Проект использует HTTP Basic Auth, конфигурация считывается из переменных окружения (`NC_USER`, `NC_APP_PASSWORD` из `.env`). Никогда не хардкодьте учетные данные.
*   **Sentinel:** Критические уязвимости, паттерны безопасности и стратегии их предотвращения, специфичные для этого кода, должны быть задокументированы в файле `.jules/sentinel.md`.

## 4. Советы для будущих ИИ-агентов

*   **Начинай с тестов:** Практикуй TDD (Test-Driven Development). Если добавляешь новую фичу (новый эндпоинт WebDAV или OCS), сначала напиши тест в `tests/test_server.py`, замокав ответ Nextcloud через `respx`, и только потом пиши реализацию.
*   **Декоратор MCP:** Для создания новых инструментов (tools) используй декоратор `@mcp.tool()`. Не забудь прописать понятный `docstring` с типизацией аргументов — именно его читает LLM на клиентской стороне!
*   **Осторожно с исключениями:** Клиент MCP не должен падать. Перехватывай `Exception` и возвращай структурированный JSON с ошибкой (`{"status": "error", "error": "..."}`). Обрати внимание на паттерн в существующих функциях в `server.py`.
*   **Изучи переменные окружения:** Обязательно ознакомься с `.env.example` при запуске, чтобы понимать, какие настройки доступны.
*   **Не ломай архитектуру:** Шлюз stateless (не хранит состояния, кроме токенов в памяти для HITL). Не добавляй базы данных или сложную локальную логику хранения.
